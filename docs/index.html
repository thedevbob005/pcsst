Framework direction

PCSST is opinionated about clarity.

Utility classes are descriptive, responsive behavior is built into named tiers, and the framework includes actual interface pieces so teams can move from prototype to system language faster.

01

Readable layouts

Use .stack, .cluster, .split-layout, and .feature-grid instead of expressing every property inline.

02

Responsive tiers

PCSST now ships .sm-*, .md-*, and .lg-* variants for common layout, spacing, and alignment changes.

03

Docs as product UI

The documentation site is not an afterthought. It uses pill navs, toolbars, command cards, app shells, and themed previews from the library itself.

04

Release automation

CI verification, GitHub Pages deployment, and tag-based package release workflows are part of the repository baseline.
