Framework direction

PCSST is opinionated about clarity.

Utility classes stay readable, variants are authored directly in CSS, and the framework includes actual interface pieces so teams can move from prototype to system language faster.

01

Readable layouts

Use .stack, .cluster, .split-layout, and .feature-grid instead of expressing every property inline.

02

Variant system

Use literal class tokens like hover:bg-accent-soft, md:grid-cols-4, max-lg:flex-col, and @md:grid-cols-2 without introducing tooling.

03

Expanded utilities

Margin, sizing, positioning, display, richer flex/grid controls, stateful color utilities, and responsive wrappers are now part of the stock PCSST surface.

04

Docs as product UI

The documentation site is not an afterthought. It uses pill navs, toolbars, command cards, app shells, and themed previews from the library itself.

What ships now

v0.4.0 pushes PCSST into a broader utility release.

  • A
    CSS-only variants State, dark, responsive, range, and container-query tokens are authored directly in the stylesheet.
  • B
    Broader utility coverage Spacing, sizing, margin, positioning, display, flex, grid, overflow, color, and transition helpers are now first-class.
  • C
    Version-aware docs Guides, library reference, themes, showcase pages, and changelog pages now teach the `v0.4.0` API directly.
